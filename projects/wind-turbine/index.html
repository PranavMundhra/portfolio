College capstone · Federated learning

Wind-Turbine

Can wind turbines learn what “healthy” looks like without pooling their data?

The question

This is my college capstone, studying federated learning for early fault detection on wind-turbine SCADA data: can turbines learn what “healthy” looks like without pooling their data?

SCADA is the monitoring system every modern turbine already runs. It records signals such as power output, wind speed, rotor speed and component temperatures, so it is a rich and inexpensive source of early warning, with no extra sensors needed.

Why it matters

Offshore turbines are hard to reach, and an unplanned failure means lost generation, emergency repairs and costly vessel and crane hire. A model that warns operators early turns an emergency into a planned repair, which is cheaper and safer.

Good early-warning models need a lot of representative data. But operators treat their SCADA data as commercially sensitive, so it is rarely shared between turbines, fleets or companies, and that limits what any one party can learn.

Why federated learning

In federated learning, each turbine trains on its own data and only model updates leave the site. A central server combines the updates into a shared model. The raw data never moves, which is what makes collaboration between data owners realistic.

What the project covers

  • Learning what normal operation looks like from healthy data alone, so no labelled faults are needed for training.
  • An open, reproducible experiment pipeline for studying federated learning on turbine data, built on a public wind-turbine benchmark.
  • Keeping the goal practical: what “early” detection actually means for a maintenance team.
  • Privacy as a design goal, not an afterthought.

How it is built

The code is a tested Python package, with the experiments driven by configuration files instead of one-off notebooks. Continuous integration runs the tests on every change.

Every reported number is meant to trace back to a recorded run. Each run stores its configuration, random seed, package versions and data fingerprints, so a result can be reproduced and checked later.

Team and context

This is a B.Tech capstone in Artificial Intelligence and Machine Learning at SVKM's NMIMS MPSTME Shirpur, academic session 2026–27. I am working on it with Anushka Sharma and Devesh Poojary, under the supervision of Dr. Praveen Kumar Loharkar. The repository was started in June 2026.

Status

A paper is in preparation, and results will be reported there. The code is open source under the MIT licence, with an archived release.
